Ultrafast & fast iteration 7

Article @dkundel Nov 20, 2026 Nov 21 edition

How I stay in the flow with Ultrafast (Dominik Kundel) ↗ 8 tips

  • Iterate on UI with Ultrafast instead of one long task. When you don't yet know exactly what a UI should look like, start with a rough direction, get something on screen fast, and react to what Codex builds with small rounds of feedback. With Ultrafast each change often takes only a couple of seconds, so you stay in the zone instead of waiting on a long high-reasoning task. #
  • Set up the fast loop: hot reload + in-app browser. Run a dev server with hot module reloading so changes show up as soon as Codex makes them, and keep the site open in the in-app browser next to the chat so you see results while you prompt. #
  • Short tasks, annotations and dictation. Send one small piece of feedback at a time. Use annotations to point at the exact element you want changed instead of describing where it is, and use dictation or voice mode to queue several small tasks while you keep looking at the result. A keyboard shortcut for dictation (or a Codex Micro) makes queuing feedback while scrolling a page quick. #
  • Start at Light/Low reasoning for quick edits. Most quick UI instructions are easy, so start with Light or Low reasoning. For something more nuanced, like designing an animation, switch to High, then go back to Low. #
  • Keep verification out of the quick loop. For small visual edits, tell Codex to focus on the code changes while you check the result in the browser yourself. Once you're happy, ask it to write the relevant tests and run the additional checks. #
  • Use the same loop for slides, documents and spreadsheets. Instead of asking for a full deck, go one slide at a time and give feedback; for documents, give feedback passage by passage as you read. Ultrafast suits tasks that rely mostly on the model's intelligence and need little validation between changes: slides, documents, spreadsheets, and computer-use tasks made of quick actions. #
  • When Ultrafast helps less. Faster token generation doesn't make the whole task 4.5× faster: if most of a turn is spent waiting on a build, test suite, compiler, other tool calls or image generation, the speedup is smaller. For well-defined tasks that need lots of experimentation and validation, or that you're happy to leave running overnight, the extra speed matters less. #
  • Try service_tier ultrafast where model time dominates. In the API, compare time spent waiting on the model versus waiting on tools. Good candidates: summaries and Q&A over a document already in context, fast tool calls and computer use (e.g. form filling, ideally with a code mode that writes a script to fill several fields at once), and voice experiences as a backend model alongside GPT-Live-1. Set service_tier to ultrafast and measure time to result. For GPT-6.2 Astra and Sol the promotional rate is 3× Standard through February 28, 2027 (6× from March 1). 3D & game workflows 3

Article @pvncher Nov 23, 2026 Nov 24 edition

Building Mont-Saint-Michel with Astra inside Unreal Engine ↗ 3 tips

  • Have Astra build editable tools, not finished scenes. Instead of having Astra generate whole scenes (USDA files or full Blender models), use it to build procedural tools inside the engine: here, PCG graphs and supporting Blueprints for roads, platforms, stairs, buildings and walls in Unreal Engine. You can then reshape a walkway or raise a terrace by hand and play the change right away, without another prompt or import pass. Article by Quentin Marmier (Epic Games) on @UnrealEngine, shared by @pvncher related ↗ #
  • Iterate on a vector map, then let the tools build it. Have Astra turn a reference into spatial rules (roads winding uphill, buildings on terraces, stairs linking heights) and draw a vector map of the layout. Iterating on that map is much faster than editing the complex procedural setup directly; the same tool collection then rebuilds the layout with terrain and connections still editable. Article by Quentin Marmier (Epic Games) on @UnrealEngine, shared by @pvncher related ↗ #
  • Ask Astra for more than you think it can do. The author's parting advice: he was at first not demanding enough of Astra and now relies on it more and more for technical work and problem-solving, including complex procedural materials. TL;DR: give it more to do than you think it can. Article by Quentin Marmier (Epic Games) on @UnrealEngine, shared by @pvncher related ↗ #

Building security review into your SDLC with Codex Security ↗ 4 tips

  • Commit a threat model and link it in Codex Cloud settings. Generate a threat model with the $codex-security:threat-model skill (or just type $threat-model in Codex), covering entry points and untrusted inputs, sensitive data paths and privileged actions. Commit it as docs/security/threat-model.md and link it in the Codex Cloud settings for the repo; without one, Codex regenerates a threat model for every security review. Revisit it when entry points, trust boundaries or privileged operations change. OpenAI Developers blog, shared by @TheRealAdamG related ↗ #
  • Seed SECURITY.md with the define-security-policy skill. AGENTS.md holds shared engineering instructions, the threat model describes the system's security reality, and SECURITY.md tells Codex how to evaluate and report against it. Run $codex-security:define-security-policy with your key policies to generate SECURITY.md, with sections such as security invariants, reportable findings, severity context (e.g. cross-tenant access is Critical) and out of scope. OpenAI Developers blog, shared by @TheRealAdamG related ↗ #
  • Pass architecture docs to CLI scans as a knowledge base. The Codex Security CLI takes supporting documents for a scan: npx @openai/codex-security scan . --knowledge-base docs/security/payment-service-context.md. Diff scans of local changes or a branch review only the proposed changes and write report.md, scan-manifest.json, findings.json (severity, confidence, locations, remediation) and coverage.json (what was reviewed, excluded or deferred). OpenAI Developers blog, shared by @TheRealAdamG related ↗ #
  • Tune PR Security Review thresholds and path overrides. Turn on Security Review for GitHub PRs at chatgpt.com/codex/cloud/settings/code-review. Automatic reviews post only High and Critical findings by default, while manually requested reviews also post Medium. Add path overrides in the repo's Codex Cloud settings to lower the threshold for sensitive paths such as auth, payments, CI workflows or infrastructure. Start with one workflow (local, PR or CLI) and expand once its findings prove useful. OpenAI Developers blog, shared by @TheRealAdamG related ↗ #

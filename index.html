OpenAI API 7

Responses API & reasoning 3

Post @OpenAIDevs Nov 19, 2026 Nov 19 edition

Reasoning items are tied to history

With GPT-6.2 in the Responses API, each reasoning item is tied to the conversation history before it, so agents can build on earlier reasoning with fewer tokens and more cache hits. Editing an earlier message makes the API drop the reasoning that follows the change. #

View post on X ↗

Responses API Background Mode (demo) ↗ 3 tips

Background Mode for asynchronous jobs, with overnight morning briefs as the example: picking a completion window and setting it on the request.

  • Background mode discounts for work that can wait. For single- or multi-turn workflows that can wait, Responses API background mode lets you pick a 2h or 8h target for the first response and save up to 40% per token versus Standard on GPT-6.2 Astra or Sol (public beta). OpenAI API › Caching & cost #
  • ▶ 0:04 Pick a completion window. Background Mode offers completion windows from Ultrafast, Fast and Standard to 2h and 8h; the longer windows are the discounted ones. #
  • ▶ 0:09 Request shape for an 8h window. Set `"background": true` and `"background_options": {"completion_window": "8h"}` on the request (shown with `gpt-6.2-sol`). Good for jobs like overnight morning briefs. #

Caching & cost 2

Post @steipete Nov 19, 2026 Nov 19 edition

Instructions-field caching bug on 6.2

A reported bug (Codex issue #62312): on GPT-6.2 Astra and Sol, content in the top-level `instructions` field of a Responses API request isn't cached, even though diagnostics report a cache hit; one report saw cache hit rates fall from 97.4% to 46.4%. Workaround: put the system prompt in a leading developer message in `input`. He landed a fix in OpenClaw's embedded harness. Quoting @bebuu_ai #
